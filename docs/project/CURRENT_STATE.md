## Known limits and risks

- No Production HA, managed PostgreSQL/object storage deployment, multi-host supervisor, human Approval, OAuth/OIDC/SSO, tenant/RBAC, broker, scheduler, autoscaling, real destructive Production remediation, or release/deploy endpoint is implemented or authorized。
- `LocalFileArtifactStore` remains the default local backend; the formal S3-compatible backend has only a single-node SeaweedFS compatibility proof. Neither backend is a managed Production security/durability, HA, replication, lifecycle, restore-SLA, or capacity conclusion; service credentials remain scoped bearer candidates。
- Statistical corpus and Agent corpus are deterministic/controlled and small. They do not establish live Provider probability, Production-scale significance, or long-term cost/latency distribution。
- Desktop/in-app browser evidence is representative where recorded; real device/iOS/mobile/PWA verification was not executed。The Web build may report a shared chunk-size warning。
- RPF-33 is directional capacity evidence, not a Production QPS/SLA/HA claim. At Large, `/metadata` returned about 21.0 MiB in 32.4 s and the unpaginated eligible list issued 502 observed SQL statements for 100 snapshots; the disposable candidate index changed the Large canonical list plan from a parallel sequential scan to an index scan, but no formal index migration was applied. The current Web list has a 100-row boundary without pagination; timeline payloads are not yet a virtualization or streaming proof. No broker, streaming artifact implementation, real GC, production topology, or retention policy was added。
- `ELIGIBLE` remains decision-only. `Agent FAIL` is not `Platform ERROR`; `UNKNOWN_OUTCOME` requires reconcile before retry。
- RPF-28 still does not establish Production isolation/HA, capacity behavior, cross-platform equivalence, broker/scheduler/autoscaling, human Approval, tenant/RBAC, real destructive remediation, or release/deploy authorization. RPF-32 does not establish managed object-storage durability, HA/replication, lifecycle/GC, versioning/Object Lock authority, multi-node supervision, capacity behavior, migration, 2PC, Production deployment, or replacement of `LocalFileArtifactStore`; metadata/object orphan cleanup remains a future retention boundary。RPF-30 does not establish long-term trace retention, a SaaS backend, alerting, Web trace UI, Production telemetry capacity, or a live Provider reliability claim; Collector export remains optional diagnostic signal, and unavailable-exporter timing remains directional evidence only. Trace/span identity is never canonical Run/Job/Attempt/evidence identity or release authority。Toxiproxy is the formal RPF-28 provider boundary, not a general Production chaos framework。
